# 沙盒仿真层：生成代码先过数字世界，真实 testbed 只跑一次性验证

生成的可执行用例在调试阶段会反复执行，而真实 testbed 拓扑被多人共享、独占成本高。为此在真实执行前增设**沙盒仿真**层：按用例声明的所需拓扑自动实例化虚拟 BBU/UE/仪表，在不接触任何射频硬件的前提下执行生成的 pytest 代码。仿真分两级保真度——**桩校验**（按 AW 操作 schema 自动生成的签名/参数校验，无行为）与**有状态仿真**（虚拟设备带状态机，AW 操作读写虚拟设备状态，可真实判定顺序依赖与断言）。沙盒复用 ADR-0003 的拉取式 Worker 机制：Worker 注册时声明能力（sandbox/real），任务携带 `execution_target`，沙盒 Worker 可多实例部署（含工程师本机），天然不与真实环境争抢资源。沙盒判决为三态：passed / failed / inconclusive（存在仅桩校验或未仿真的步骤时不可判定）。射频级数字孪生明确不在本层范围。

**Considered Options**:
- 仅提供固定返回值的 AW 桩（L1）：能挡映射/渲染错误，但断言在固定返回值下永远假绿或假红，挡不住用例语义错误，调试无意义。
- 射频级数字孪生（L3）：信道仿真与真实测量值成本是有状态仿真的数量级以上，且依赖专用仪表厂商方案，MVP 不可行。
- 后端进程内直接跑 pytest：破坏 Worker 隔离，后端被迫安装 AW 依赖。
- 允许调试时直接编辑生成的代码：迭代看似更快，但代码脱离模板渲染血缘，五环追溯在代码环断裂，且为"手工补丁进真实硬件"开了 ADR-0001/0002 之外的第二道风险门；改为**只许上游修复**——映射错回确认态改映射，文本错改文本重新映射，修完重新 generate 新版本，代码永远 100% 由系统渲染产出。

**Consequences**:
- 操作目录每个条目须声明仿真供给形态：`simulatable: schema_stub | declarative | python | none`。L1 桩由 schema 自动生成；L2 优先用声明式效果描述符（写哪些虚拟设备状态路径、读哪些、预置返回/错误），表达不了的复杂操作以命令式纯 Python 仿真（独立包、无硬件 SDK 依赖）作逃生舱。**仿真实现所有权归 AW 团队，随 catalog 一起交付**，本系统团队不手写仿真，避免仿真与真实 AW 漂移、责任不清。
- 不可仿真的步骤在沙盒中如实报错/跳过并逐步骤标注"仿真通过/仅桩校验/未仿真"，报告与前端禁止把 inconclusive 展示为绿色通过；inconclusive 允许提交真实执行但需二次确认。宁可诚实挡住，不许假绿。
- 新增独立的**调试会话（debug_run）**记录，关联 executable_case 版本，保留最近 N 次，不进正式执行历史、不进五环追溯；状态机不加新状态，沙盒调试在 `generated` 态内闭环（generate → 沙盒跑 → 回上游修 → 重新 generate），只有正式 execute 才转 queued。
- 虚拟拓扑按 required_topology 自动实例化为标准默认态；工程师可在调试面板修改初始状态并保存为该用例的调试预设（仅存于 debug_run 上下文，不进用例正式数据）。
- 沙盒执行不做 LASS 三值环境校验（虚拟设备永远"存在"），报告环境区块明确标注"仿真执行未进行环境校验"；真实路径的环境校验逻辑原样不动。
- `execution_task` 增加 `execution_target enum[sandbox|real]`，Worker 需启动注册（worker_id、capabilities、sim_package_version、心跳），claim 按能力过滤；沙盒报告记录仿真包版本，为仿真与 catalog 漂移排查留证据。
- 失败注入（故意令某步报错以验证断言/清理分支）出 MVP，声明式效果描述符 schema 预留 fault 字段位置，二期加面板。
